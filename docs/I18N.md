# Languages (i18n)

Overlap speaks 20 languages. The page uses the language chosen in the footer
(remembered in the browser's localStorage as `overlap.lang`), otherwise the best
match for the browser's languages (`navigator.languages`), otherwise English.
Arabic is right-to-left (`<html dir="rtl">`).

## Files

| Path | What |
| --- | --- |
| `shared/i18n/languages.js` | The language list (codes, names in their own language, direction) and `matchLanguage()` |
| `shared/i18n/core.js` | Message lookup, plurals (`Intl.PluralRules`), `{placeholder}` filling |
| `shared/i18n/en/<namespace>.js` | **English source text**, one file per part of the app |
| `shared/i18n/en.js` | All English text in one file, **generated** by `npm run i18n:merge` |
| `shared/i18n/<code>/<namespace>.js` | Each translation's source, mirroring `en/` (plus `_glossary.txt`, the translator's term list) |
| `shared/i18n/<code>.js` | Each translation in one file, **generated** by `node scripts/i18n.mjs assemble <code>` |
| `shared/i18n/catalogs.js` | Every language, statically imported, for the server's emails; **generated** by `npm run i18n:merge` |
| `public/js/lib/i18n.js` | Browser runtime: `t()`, `tx()`, `locale()`, `setLanguage()` |
| `scripts/i18n.mjs` | `merge` (build `en.js`) and `check` (every language has every key, matching placeholders and plural forms) |

## Writing code

```js
import { t, tx, locale } from '../lib/i18n.js';

h('button', null, t('guest.submit'))                      // plain text
t('guest.timesAvailable', { count: 3 })                    // plural: picks the form for 3
h('p', null, ...tx('guest.signIn', { link: h('a', …) }))   // rich text: {link} becomes the node
new Intl.DateTimeFormat(locale(), …)                       // dates, times, numbers
```

Rules:

1. **Every visible or spoken string** goes through `t()` or `tx()`: text,
   button labels, `aria-label`, `title`, `placeholder`, `announce()` messages,
   dialog titles and buttons, error messages, `document.title`.
2. **Never call `t()` at module top level.** Modules load before the language
   does. Put text inside functions (a `const LABELS = () => ({ … })` is fine).
3. **Keys** are `namespace.camelCaseName`, the namespace being the file's part
   of the app (`guest.`, `manage.`, `pollForm.`, `grid.`, …). Keys describe
   meaning, not wording: `guest.submit`, not `guest.submitAvailability`.
4. **Placeholders** are `{name}`. Never build sentences by joining fragments
   (`'Thanks, ' + name`); word order differs between languages. Use one key
   with placeholders: `'Thanks, {name}. Your times are in.'`.
5. **Plurals**: the value is an object of plural forms and the call passes
   `count`: `{ one: '{count} time', other: '{count} times' }` with
   `t('…', { count: n })`. Don't use `f.plural()` (English only).
6. **Rich text**: links or buttons inside a sentence are `{placeholders}` filled
   by `tx()` with nodes; the link's own text is its own key.
7. **Don't translate**: CSS classes, `data-*`, ids, URLs, poll titles and other
   things people typed, the product name "Overlap", "Micropeptide", "Resend",
   "GitHub", "Cloudflare", time zone ids.
8. **English stays exactly as it was**, character for character (curly quotes
   and apostrophes included). Tests read the English text.
9. Dates, times, numbers and durations come from `Intl` with `locale()`, never
   hand-built.

## Server errors and emails

The API sends `{ error, field, code, vars }`. `error` is English, for API users;
the browser shows `t('errors.<code>', vars)` when that key exists. Every
`HttpError` gets a stable `code` (`snake_case`) and the values its message needs
in `vars`. Emails are written in the language of the person who asked for them
(stored with the subscription) using the same catalogs (`email.` keys).

## Translating

Each `shared/i18n/<code>.js` is `export default { 'key': 'text', … }` with
**exactly** the keys of `en.js`.

- Keep every `{placeholder}` exactly as in English (same names, none added or lost).
- Plural values are objects with the plural categories of that language:
  `new Intl.PluralRules('<code>').resolvedOptions().pluralCategories`
  (Japanese, Chinese, Korean, Vietnamese, Indonesian and Thai have only `other`;
  Russian, Ukrainian and Polish have `one`, `few`, `many`, `other`; Arabic has
  `zero`, `one`, `two`, `few`, `many`, `other`).
- Natural, friendly, plain language, as a native-speaking product writer would
  write it; the informal "you" where that is the norm for consumer apps (es tú,
  de du, fr vous, …). Keep it as short as the English where possible: buttons
  and labels have limited room.
- Keep "Overlap" untranslated. Keep typographic quotes natural for the language
  (« » in French, „ “ in German, 「」 in Japanese, …).

Workflow after changing English text: edit `shared/i18n/en/<namespace>.js`,
`npm run i18n:merge`, update the same key in each `shared/i18n/<code>/<namespace>.js`,
`node scripts/i18n.mjs assemble <code>` for each, then `npm run i18n:check`
(also part of `npm test`), which must pass before publishing. A missing
translation falls back to English rather than breaking the page.

Emails: the browser sends its language with "Email me"; the server stores it with
the subscription (`email_subs.lang`) and writes that person's emails, including
digests, in it. Names in a list are joined with `email.nameSeparator`.
